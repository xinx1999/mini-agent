# Mini Agent（TypeScript，零依赖）

一个能自己决定"该调哪个工具"的 AI agent：会联网搜索、会检索本地文档、能多轮对话、
支持流式输出和上下文压缩。**不依赖任何第三方框架。**

**线上版本**：已部署，可直接访问。该平台每次重新部署都会生成新链接，
所以这里不写死地址——最新地址以最近一次部署的返回为准。

代码量：主体约 1600 行（其中注释占了将近一半）、前端界面 457 行、测试 1069 行。

写它的目的不是做产品，而是把 agent 的本质摊开——整个核心就是一个 `for` 循环，
读完你就知道 LangChain 那些概念在替你做什么。

## 怎么跑

环境要求：**Node 22+**（内置 TypeScript 类型擦除和 fetch，所以不需要 `npm install`）。

```bash
cp .env.example .env      # 填上你的模型 key

node --env-file=.env index.ts "帮我看看这个目录有什么"   # 单次
node --env-file=.env index.ts                            # 交互模式（多轮，历史落盘）
node --env-file=.env server.ts                           # 网页版，然后开 http://localhost:3000
```

交互模式下 `/reset` 清空当前会话记忆，`/exit` 退出。`AGENT_SESSION=xxx` 可以开多个互不干扰的会话。

想不花 token 看界面，跑 `npm run demo`（用假模型，回答是写死的脚本）。

## 代码导读

**按这个顺序读，别跳：**

| 文件 | 作用 | 读的时候注意 |
|---|---|---|
| `src/types.ts` | 词汇表 | 看懂这几个类型，就看懂所有框架在传什么 |
| **`src/agent.ts`** | ★ **核心** | 整个 agent 就是一个 `for` 循环 |
| `src/tools.ts` | 工具集 | description 写得比代码细——那是模型唯一的判断依据 |
| `src/llm.ts` | 通信层 | 流式解析 + 重试。`tool_calls.arguments` 是按 index 分片拼的 |
| `src/trace.ts` | 可观测性 | 每步的 token 和耗时。没有它，出问题只能靠猜 |
| `src/memory.ts` | 记忆 | 存的是**完整**的 messages，含工具调用往返 |
| `src/rag.ts` + `src/docs.ts` | 文档检索 | TF-IDF + 余弦，中文用 bigram 切词 |
| `src/search.ts` | 联网搜索 | 抓 Bing 结果页。`fetchImpl` 可注入，测试不真打网络 |
| `src/compress.ts` | 上下文压缩 | 历史超阈值时把早期对话交给模型总结 |
| `server.ts` | HTTP 层 | Node 内置 http 模块，没有框架 |
| `web/index.html` | 界面 | 原生 HTML/CSS/JS 单文件，不依赖构建工具 |

```
agent 的本质 = 一个循环：
    调模型 → 它要工具就给工具结果 → 再调模型 → 直到它不再要工具
```

## 设计取舍

| 决定 | 为什么 |
|---|---|
| 不引入任何框架 | 目的是理解本质。核心循环只有 200 多行，读完就知道框架在替你做什么 |
| RAG 用关键词不用向量 | 向量需要 embedding 服务且**不可复现**——同样输入两次结果可能有细微差别，测试写不了断言 |
| 中文检索用 bigram | 没有分词器。「人工智能」→ 人工/工智/智能，够用 |
| 流式只做在连接层重试 | 一旦开始 yield 内容，重试就会让用户看到重复的半截回答 |
| 检索/摘要函数可注入 | 测试不用真打网络、不用真烧 token，结果完全确定 |
| 失败喂回模型而非中断 | 模型会编不存在的工具名、工具也会失败。错误是"给模型的输入"，不是程序的终点 |
| `maxSteps` 兜底 | 循环不保证自己会停。跑满了要明确说"未完成"，不能假装给了答案 |

## 已知局限

- **搜索质量不全由我们决定**：抓的是 Bing 的 HTML，对方改版或按出口 IP 给不同缓存时，
  结果会变差。解析做得宽松（拿不到字段就跳过），但料不到内容本身的变化。
- **压缩会丢细节**：早期对话只留摘要。这是"无限增长"和"丢信息"之间的取舍。
- **原型级界面**：`web/index.html` 是单文件手写的，够演示，不是产品级工程。

## 自己动手改（由易到难）

1. **加一个工具**——比如 `get_weather`，看模型会不会自己选它
2. **把 `maxSteps` 改成 2**——看兜底返回什么。注意它明确说"未完成"，不假装给了答案
3. **删掉 `agent.ts` 里"出口处那条 push assistant"**，跑 `multi-turn.mjs`，看哪条断言挂
4. **每步之后打印整个 `messages` 数组**——直观看到上下文怎么变长，就明白为什么要压缩
5. **给 `web/index.html` 加一个深/浅色切换**——顺便熟悉这个单文件界面的结构

## 安全提醒

- `.env` 会随代码上传到部署沙箱。别人拿不到源码，但 key 在沙箱里——**建议用可随时吊销的小额 key**。
- `list_files` 默认过滤 `.env*`。将来若加"读文件内容"的工具，**过滤必须同步做**，
  否则密钥会被原样读出来发给第三方。
